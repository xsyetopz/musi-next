# 1.1 Confirmed Decisions

Status: reference index for the addendum decisions.

## Unsafe and pinning

- `unsafe` is checked lexical authority for explicitly unsafe operations.
- `unsafe` does not disable normal checking.
- `unsafe` does not pin, root, extend lifetimes, suppress GC, or bypass write barriers.
- `pin` is checked lexical address/movement stability.
- `pin` creates a lexical Immix pin region.
- `pin` does not grant unsafe authority.

## Runtime model

- Musi uses a Generational Immix VM/runtime model.
- Ordinary managed storage is movable.
- Ordinary Musi layout is implicit, private, and VM-owned.
- Source code must not assume managed address stability except through `pin` or explicit non-moving storage.

## Pointer/resource family

- `Ptr[T]` / `Ptr[mut T]` are replaced by `RawPtr[T]` / `RawPtr[mut T]`.
- `Root[T]` is a VM-owned stable token to a Musi-managed value.
- `Host[T]` is a host-owned resource/object/service/value exposed to Musi.

## Host interop and raw FFI

- Host interop is VM-aware and safe by default.
- Host interop is the normal embedding/scripting path.
- Raw FFI is ABI-aware and unsafe by default.
- Raw FFI uses `@foreign(...)` declarations.
- Direct `@foreign(...)` calls require `unsafe`.
- No `foreign` keyword exists.
- No foreign block syntax exists.

## Retention

- All foreign parameters are non-retaining by default.
- Retention is never inferred from type alone.
- Retention requires named retention groups.
- `@retains(...)` is the compact metadata attribute for non-default retention.
- Retained Musi-managed values use `Root[T]`.
- Host-owned resources use `Host[T]`.
- A `RawPtr` produced from a pin region cannot outlive that pin region.
- A `RawPtr` into movable managed storage cannot be retained.

## Layout

- Layout metadata is only for external representation contracts.
- Ordinary Musi layout remains implicit, private, and VM-owned.
- Layout metadata uses compact presets plus explicit representation overrides.
- No `packed` keyword exists.
- Packing is a layout policy.
- Externally laid-out data may contain only fields with explicit external representation.
- Ordinary Musi-managed values do not become externally laid out merely by appearing in externally laid-out data.

## Imports and opacity

- Imports are bound through ordinary `let name := import "...";` syntax.
- No standalone import namespace syntax is introduced.
- `opaque` and `erased` retain their existing meanings from the 1.0 candidate pack.
- `Host[T]` does not require a new opaque-resource declaration family.
